# 4대 AI 코딩 에이전트 프레임워크 비교

> 순위가 아닌 특성 비교. 본인에게 맞는 것을 쓰거나 필요한 부분만 조합해서 사용한다.

---

## 1. oh-my-claudecode (Yeachan-Heo)

### 특징
- Claude Code를 위한 **다중 에이전트 오케스트레이션** 프레임워크, 19개의 전문 에이전트 지원 (아키텍처, 연구, 디자인, 테스트 등)
- **tmux**를 활용해 Codex, Gemini, Claude CLI 창을 실제로 여러 개 띄워 백그라운드 프로세스 기반의 병렬 작업 수행
- 터미널 하단에 오케스트레이션 지표 및 에이전트 작업 상태를 실시간으로 보여주는 **시각적 HUD 상태 표시줄** 제공
- 복잡한 작업 시 Codex와 Gemini에게 동시에 질문하고 Claude가 종합하는 **3중 모델 합성 자문** 기능

### 장점
- 초기 설정 최소화, 지능적인 기본값으로 즉시 작동
- **스마트 모델 라우팅** — 단순 작업엔 Haiku, 복잡한 작업엔 Opus를 자동 할당 → 토큰 비용 30~50% 절감
- Rate Limit 자동 감지 및 해제 즉시 세션 자동 재개

### 단점
- 병렬 터미널 워커 실행 기능을 쓰려면 **tmux 필수** → Windows 사용자는 psmux 또는 WSL2 별도 설정 필요

## 2. everything-claude-code (affaan-m)

### 특징
- **성능 및 토큰 비용 최적화**에 극도로 초점을 맞춘 거대한 생태계 — 47개 에이전트, 181개 스킬
- **DRY 어댑터 패턴** 적용 → Claude Code 외에 Cursor, OpenCode, Codex CLI 등 다양한 환경 완벽 호환
- **AgentShield** — 3개의 Opus 에이전트(공격자, 방어자, 감사자)가 실제 해킹 시나리오를 시뮬레이션하고 취약점 분석
- **본능(Instinct) 기반 지속 학습** + GitHub App 연동 → 수만 개의 커밋 기록에서 재사용 가능한 코딩 패턴 자동 추출

### 장점
- 논리적 중단점에서 컨텍스트 압축 + 사고(Thinking) 토큰 제한 설정 → 토큰 비용 최대 60~70% 절감
- UI 프레젠테이션 자동 생성, 비디오·오디오 미디어 생성 파이프라인 등 압도적으로 넓은 기능 범위
- Rust로 작성된 실험적 제어 대시보드 **ECC 2.0 Alpha** 제공

### 단점
- 방대한 설정 파일·스킬·훅 수 → 초보자의 **학습 곡선이 매우 높음**
- MCP 서버를 너무 많이 활성화하면 200k 컨텍스트 윈도우가 급격히 감소 → 세심한 관리 필요

## 3. gstack (garrytan)

### 특징
- Y Combinator CEO Garry Tan의 실제 개발 방식 반영 — CEO, 수석 디자이너, QA 리드, 엔지니어링 매니저 등 **23개의 직책** 부여, 실제 스타트업 팀처럼 작동
- 캡차 우회 및 안티 봇 기능이 탑재된 **'GStack 브라우저'** — AI가 직접 화면을 보며 탐색하고 UI/UX QA 테스트 수행
- AI 디자인 시안 4~6개를 병렬로 생성해 시각적으로 비교, 선택된 시안을 반응형 **프로덕션 수준 HTML**로 자동 변환
- Claude와 Codex 등 다른 AI 에이전트가 동일한 브라우저의 격리된 탭을 공유하며 실시간으로 협업하는 **브라우저 공유 파이프라인**

### 장점
- 기획서 작성 → 아키텍처 설계 → 자동 배포 → 배포 후 문서 최신화 → 팀 회고록 작성까지 **소프트웨어 생애주기 전체 자동화**
- **Conductor** 기능 — 격리된 작업 공간을 가진 10~15개의 Claude Code 세션(스프린트)을 동시 지휘 → 1인 개발자 생산성 극대화
- 자연어 음성 입력 호환 → 명령어 암기 불필요

### 단점
- '생각 → 기획 → 개발 → 리뷰 → 테스트 → 배포' 방법론이 툴에 **강제적으로 녹아 있어** 유연한 애자일 방식 선호자에게는 경직될 수 있음
- Bun 런타임, Playwright 등 특정 인프라 의존 → Windows에서 초기 환경 구성 시 예기치 않은 오류 가능성

## 4. superpowers (obra)

### 특징
- 순수한 소프트웨어 개발 **'방법론 강제화'** 프레임워크 — 코딩 시작 즉시 기획 요구, 격리 브랜치 생성, 작업 분할 흐름이 자동 강제 실행
- 극단적인 **TDD (RED-GREEN-REFACTOR 사이클)** 강제 — 실패 테스트를 먼저 통과시키지 않은 로직 코드는 강제 삭제
- **Git Worktree** 활용 → 작업 시작 시 완전히 격리된 개발 브랜치 환경 자동 세팅
- 근본 원인 추적, 심층 방어 구축 등을 강제하는 **4단계 체계적 디버깅 파이프라인**

### 장점
- 'AI Slop(저품질 코드)'을 원천 차단, 엄격한 테스트 강제 → **인간 시니어 개발자 수준의 엔지니어링 품질** 보장
- 소크라테스식 문답으로 요구사항을 잘게 쪼개 하위 에이전트에게 할당 → **사람 개입 없이 몇 시간 동안** 코드 리뷰·작성을 반복하며 스스로 완성

### 단점
- 빠른 프로토타이핑이나 단순 스크립트 작성 목적에는 **진행 속도가 너무 느리고 답답**할 수 있음
- 설계 승인 과정·테스트 코드 작성을 건너뛸 수 없고 규칙 위반 시 코드 삭제 → TDD에 익숙하지 않은 사람에게는 **진입 장벽이 매우 높음**
