# 토스 DataOps — 머릿속 맥락을 AI 스킬로 꺼내기

원문: [toss.tech/article/dataops-log-definition-skill](https://toss.tech/article/dataops-log-definition-skill)

## 문제: 규칙은 문서에, 맥락은 머릿속에

**DataOps Manager**: 사용자가 앱에서 어떤 화면을 보고 뭘 눌렀는지 어떻게 기록할지 정하는 비개발자 직군.

규칙 문서('앱로그 백과사전')는 있었지만, **진짜 중요한 맥락은 문서에 없었다.**

> `card_company`라는 이름으로 이미 기록되던 정보를  
> 다른 사람이 못 찾고 `issuer`라는 새 이름으로 또 만드는 위험.  
> 같은 정보가 두 이름으로 쌓이면 나중에 분석이 꼬인다.

## 스킬의 작동 순서

```
화면 확인 → 규칙 확인 → 이미 있는 기록 전수 탐색
→ 재사용 제안 (먼저) → 새로 만들기 (마지막)
```

**핵심**: AI가 마음대로 반영하지 않는다.
- 확신 없는 건 사람에게 질문
- 바뀔 내용을 미리 보여준 후 **사람이 확정해야만 반영**

## 실제 사용 결과

> "거의 다 기존 걸 재사용했고 새로 만든 건 1개뿐이었다.  
> 재사용하려던 값이 알고 보니 다른 기능 전용이라는 것도 짚어줘서 섞일 뻔한 걸 막았다.  
> '이렇게 바뀔 거예요'를 먼저 보여줘서 안심이 됐다."

## 문서 구조 설계 교훈

처음엔 규칙·절차를 **문서 하나**에 다 넣었더니 → AI가 중요한 규칙을 놓쳤음.

→ **작업별로 문서를 쪼개고**, 스킬엔 "어디 가서 읽으라"는 길 안내만 남김.

## 일하는 방식의 변화

| 이전 | 이후 |
|------|------|
| 현업 → 플랫폼팀에 수정 요청 → 대기 | 현업이 직접 스킬 제작 → 플랫폼팀 검토·배포 |

## 핵심 인사이트

> **품질을 가른 건 규칙이 아니라 맥락이었다.**
