# Stageshow — 에이전트가 실제 제품처럼 보이는 가짜 제품 UI·커서 데모를 만들게 하는 스킬

- 저장소: https://github.com/benjitaylor/skills (Stageshow v1.1.1, 스킬마다 라이선스 별도 표기)
- 설명 글: https://benji.org/stageshow
- 설치: `npx skills add benjitaylor/skills --skill stageshow`
- 소개 글: @adrien.ninet (Threads, 2026-11-17) — "AI slop 대신 디자인을 10배 끌어올리는 스킬" 4개 중 하나

## 무엇을 만드나

브라우저·앱 창, 대시보드, 휴대폰, 알림, 터미널, 벤토 그리드, 커서 시연을 **실제 제품처럼 보이는 가짜 UI**로 만든다. 정지 일러스트 하나, 또는 한 가지 일이 일어나는 짧은 애니메이션이다. 마케팅 페이지 히어로, 기능 카드, 문서 히어로에 맞게 틀을 잡고 잘라 낸다. 브라우저 자동화가 아니라 그려 낸 일러스트다 (`a.click()`은 커서가 누르는 모습을 그리고, `a.set()`은 장면을 바꾼다).

## 핵심 원칙

> 실제 제품처럼 읽히되, 보는 사람에게 필요한 만큼만 단순하게. 의도를 갖고 틀을 잡고, 모든 움직임에는 이유가 있다.

실패하는 다섯 가지:
- **너무 많음**: 모든 줄에 진짜 글자와 숫자를 채운다. 디테일이 많을수록 생성된 티가 난다.
- **와이어프레임**: 회색 덩어리 두 개와 버튼 하나. 너무 작게 만들었거나 알아볼 만한 요소를 다 뺐다.
- **상자에 갇힘**: 창 전체를 카드 안에 균일한 여백으로 줄여 넣는다. 제품 사진이 아니라 붙여 넣은 스크린샷이 된다.
- **평평함**: 모든 요소가 같은 무게, 같은 테두리 카드. 시선이 머물 곳이 없다.
- **밋밋함**: 요청이 무엇이든 회색 창과 커서. 요청한 분위기(청사진, 유리 효과, 마스코트 등)가 핵심이다.

해법: 차분한 회색으로 채운 구조가 있는 화면, **이야기에 필요한 곳에만 진짜 글자**(보통 3~7개)를 쓰고 나머지는 자리 표시 줄로 둔다. 숨 쉴 여백을 두고, 시선이 이야기로 가도록 잘라 낸다. 글자는 줄이되 맥락은 줄이지 않는다.

## 작업 순서 (SKILL.md 요약)

1. **매체와 자리**: 정지인지 애니메이션인지, 들어갈 페이지와 폭. 보일 크기로 디자인한다 (히어로 옆 약 720×340, 전폭 히어로 900~1100, 카드 400×300). 휴대폰 칸(358)에 들어갈 수 있으면 줄이는 게 아니라 다시 디자인한 `compact` 버전을 함께 만든다.
2. **룩**: 제품의 코드나 사이트가 있으면 그 토큰을 키트 토큰에 맞춘다. 없으면 테마(라이트·다크·청사진·유리), 팔레트, 충실도(`minimal`·`standard`·`realistic`)를 고른다. 기본은 라이트·강조색·standard.
3. **이야기**: 3~5개 비트와 결말, 10~16초. 설명할 수 없는 커서 움직임은 넣지 않는다. 더 풍부한 이야기와 더 차분한 화면 중에서는 화면을 고른다.
4. **예시에서 시작**: 가장 가까운 기준(gold) 예시를 촬영해 보고 그 폴더를 복사해 시작한다. 구조(무대 크기, 자르기, 줄·글자 크기, 간격, 비트)는 유지하고 룩과 내용만 요청한 제품으로 바꾼다. 이름만 바꾼 복사본은 끝난 게 아니다.
5. **화면**: 진짜 글자 개수를 정해 두고 키트의 `Bar`, `Text`, `Row`로 짓는다.

## 들어 있는 것

- **React 키트** (`kit/`): React 18 이상, 서드파티 애니메이션 런타임 없음. 프로젝트에 복사해 `Stage`, `Window` 등을 쓴다.
- **기준 예시와 실제 제품 연구**: Figma, Linear, Slack, Raycast 등을 본뜬 예시, 시각 스타일 9종, 나쁜 예·좋은 예 짝.
- **미리보기 플레이그라운드**: `npm install && npm run dev`. 일시정지·되감기·느리게·한 프레임씩, 휴대폰 폭(358px), 모션 줄이기 보기.
- **촬영 검증 도구**: `node scripts/film.mjs '<URL>' --select '.your-demo' --gate`로 정지 컷·휴대폰 폭·상태별 화면을 찍어 에이전트가 결과를 스스로 확인한다 (`playwright-core`와 로컬 Chrome 사용). README는 "자동 검사 결과가 모션을 직접 보는 것을 대신하지 않는다"고 적고 있다.
