# rederive — 질문으로 설계를 다시 끌어내는 스킬

- 저장소: https://github.com/EricJujianZou/rederive (MIT, 저장 시점 약 1,600⭐)
- 소개 글: @developk88 (Threads, 2026-11-24) — "오픈소스 저장소 공부용으로도 괜찮겠다."
- 부제: "답답한 개발자가 인간의 호기심을 되살리려는 시도"

## 무엇인가

AI가 짜 준 코드를 면접이나 업무에서 **설명할 수 있게** 돕는다. 저장소의 각 부분을 **나라면 어떻게 만들지** 묻고, 사용자가 설계 결정을 스스로 다시 끌어내게(re-derive) 한다.

**설명을 해 주지 않고 질문만 한다** — 일부러 그렇게 만들었다. 에이전트의 말을 외우는 대신, 끌어내면서 이해하게 하려는 것이다.

예: "요청마다 인증을 어떻게 처리할래?" 식으로 조건을 좁혀 가다 보면 미들웨어 체인 같은 설계를 스스로 떠올리게 된다.

## 동작 방식

- **프로젝트가 왜 있는지부터 시작**: 내 저장소면 왜 만들었는지 묻고, 남의 저장소면 원래 풀려던 문제를 찾아 "너라면 어떻게 풀래?"라고 묻는다.
- **답하는 동안 뒤에서 에이전트가 저장소 지도를 만든다**: 코드, 파일 사이 import 연결, 설계가 바뀐 커밋을 읽는다. 커밋 메시지는 믿지 않는다 (AI로 큰 커밋 몇 번에 만든 저장소도 다루려고).
- **지도에는 문제 5~10개**가 시스템을 만들 순서대로, 각각의 제약과 실제 설계와 함께 들어 있다 (`.rederive/map.md` — 답이 들어 있으니 끝날 때까지 열지 말 것).
- **막히면** 고를 수 있는 접근 몇 가지로 문제를 좁혀 준다. 두 번 연속 틀리면 문제를 그려 주겠다고 제안한다.
- **문제를 하나 풀 때마다** 그 설계가 코드 어디에 있는지(읽을 파일과 함수 순서, 그걸 추가한 커밋)를 알려 준다. 코드는 보여 주지 않고 직접 읽게 한다.
- **어디서 막혔고 무엇을 혼자 풀었는지** `.rederive/log.md`에 기록한다. 끝나고 읽으면 무엇을 연습할지 보인다.

모두 내 컴퓨터에 남는다. `.rederive/`는 로컬 git 제외 목록에 들어가 커밋에 나타나지 않는다. **텔레메트리 없음.**

## 설치·사용

```bash
npx skills add EricJujianZou/rederive    # Claude Code, Codex, Cursor 등 약 70개 에이전트
```

필요: `git`, `bash`, `python3`. Claude Code 플러그인으로도 설치할 수 있다.

```text
/rederive                                       # 지금 있는 저장소
/rederive ~/code/myapp                          # 로컬 저장소
/rederive https://github.com/expressjs/express  # 남의 저장소 (현재 폴더에 clone)
```

평소 말로 대화한다: 막혔다고 하거나, 문제를 건너뛰자고 하거나, 처음부터 다시 하자고 한다.
