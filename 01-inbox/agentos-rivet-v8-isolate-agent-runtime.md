# agentOS — 크롬 V8 격리 기술로 에이전트를 탭처럼 돌리는 런타임

- **GitHub**: https://github.com/rivet-dev/agent-os
- **문서**: https://rivet.dev/docs/agent-os/
- **설치**: `npm install rivetkit`
- **상태**: 오픈소스, 베타 공개

## 핵심 아이디어

기존 AI 에이전트 실행 방식(가상 서버, 컨테이너)은 무겁고 느리고 비싸다. agentOS는 크롬이 탭을 격리하는 **V8 isolate** 기술을 에이전트에 그대로 적용했다.

> "에이전트 한 개 = 크롬 탭 한 개" 수준의 무게로 실행

## 성능 비교

| 항목 | 기존 방식 | agentOS | 차이 |
|------|-----------|---------|------|
| 시작 시간 | 3초+ | **6ms** | 516배 빠름 |
| 메모리 | 1GB+ | **131MB** | 1/8 |
| 비용 | 기준 | — | **1/32** |

수십~수백 개 에이전트를 동시 운영하는 서비스에서 비용 차이가 직접적으로 나타난다.

## 왜 V8 Isolate인가

크롬에서 탭 하나가 죽어도 다른 탭은 정상이다. 이 탭 격리 기술(V8 isolate)이 핵심:
- 운영체제 전체를 띄우는 게 아니라 필요한 만큼만 격리된 공간 생성
- 에이전트끼리 완전히 분리 → 한 에이전트가 다른 에이전트 데이터에 접근 불가

## 설치 및 사용

```bash
npm install rivetkit
```

Docker 불필요, 가상 서버 불필요. 기존 서버 코드 안에 에이전트가 내장되는 구조. 코드 10줄이면 에이전트 실행·프롬프트 전송·결과 수신까지 가능.

**실행 환경**: 노트북, Vercel, AWS, Google Cloud, 라즈베리 파이 — 어디서든 동일하게 작동.

## 주요 기능

### 파일 저장소 연결
에이전트에 S3, SQLite, Google Drive, 로컬 폴더를 폴더처럼 마운트. 인증 키는 서버가 관리하고 에이전트는 파일만 접근.

### 보안
- 에이전트별 컴퓨팅 자원 상한 설정
- 에이전트별 네트워크 접근 개별 제어
- 사람 직접 승인 / 자동 승인 혼합 권한 관리

### 오케스트레이션 (기본 내장)
웹훅, 멀티플레이어 관찰, 에이전트 간 위임, 자동 재시도, 작업 대기열, 영구 저장소, 크론 스케줄

```
"매일 9시에 코드 보안 점검 후 보고서 작성" → 에이전트가 알아서 실행
```

### 하이브리드 실행
기본은 경량 V8 isolate, 브라우저 조작·코드 컴파일 등 무거운 작업이 생기면 그때만 풀 환경을 즉시 올림.

## 지원 에이전트

- **현재**: Pica
- **곧 지원 예정**: Claude Code, Codex, Amp, OpenCode

## 포지셔닝

> "사람한테 Windows·macOS가 있듯, 에이전트한테도 안전하게 돌아갈 수 있는 바닥이 필요하다."

에이전트가 파일을 읽고, 명령을 실행하고, 네트워크에 접근하고, 다른 에이전트와 협력하는 인프라 계층을 노리는 포지션.
