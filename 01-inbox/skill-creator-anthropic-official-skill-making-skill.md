# skill-creator — 스킬을 만들어 주는 스킬

- 위치: https://github.com/anthropics/skills 의 `skills/skill-creator` (저장소는 Anthropic 공식, 저장 시점 약 20만 6천⭐. GitHub는 라이선스를 한 가지로 표기하지 않았다 — 스킬마다 다를 수 있다)
- 빈 양식: 같은 저장소의 `template/SKILL.md`
- 소개 글: @njobbooking (Threads, 2026-11-26) — "'그럼 내 스킬은 어떻게 만드나요'라는 반응이 많았다. 직접 쓸 필요가 없다."

## 소개 글의 핵심 4가지

1. **이름은 skill-creator**, Anthropic 공식 저장소에 같이 들어 있다.
2. **평소 하던 일을 말로 설명**하면 된다. 예: "견적서는 이 순서로, 이 문구는 꼭 넣고, 금액은 이렇게 적는다" → SKILL.md 형태로 정리해 준다.
3. **필수 항목은 두 줄뿐**: `name`(이름)과 `description`(언제 쓰는지). 나머지는 평소 하던 말 그대로 적는다.
4. **처음엔 짧게 만들고 쓰면서 고친다.** 한 번에 완벽하게 쓰려고 하면 시작을 못 한다.

## skill-creator가 실제로 하는 일 (SKILL.md 확인)

소개 글보다 넓다. 스킬 하나를 **만들고 평가하고 고치는 반복 과정 전체**를 돕는다.

1. 스킬이 무엇을 할지, 대략 어떻게 할지 정한다
2. 초안을 쓴다
3. 테스트 프롬프트 몇 개를 만들어, 그 스킬을 쓰는 Claude를 돌려 본다
4. 결과를 **정성적·정량적**으로 평가한다 (돌리는 동안 정량 평가 항목을 초안으로 짜고, 결과 보기 화면을 열어 준다)
5. 평가를 바탕으로 스킬을 다시 쓴다
6. 만족할 때까지 반복하고, 테스트 범위를 넓혀 다시 해 본다
7. 끝나면 **description 개선 스크립트**로 스킬이 제때 불리도록 다듬는다

사용자가 어디쯤 와 있는지 파악해 그 단계부터 돕는다 (스킬 아이디어만 있으면 좁히는 것부터, 이미 초안이 있으면 평가·반복부터). "평가는 필요 없고 같이 분위기로 만들자"고 하면 그렇게도 한다.

**의도 파악 질문**: ① Claude가 무엇을 할 수 있게 하나 ② 언제 작동해야 하나(어떤 말·상황) ③ 기대하는 출력 형식 ④ 테스트 케이스를 둘지 — 파일 변환·데이터 추출·코드 생성처럼 결과를 객관적으로 확인할 수 있는 스킬은 테스트 케이스가 도움이 되고, 글쓰기처럼 주관적인 출력은 덜 필요하다.

**SKILL.md 구성 요소**: `name`(식별자), `description`(언제 쓰고 무엇을 하는지 — 작동을 일으키는 **핵심 장치**라서 "언제 쓰는지"는 본문이 아니라 여기에 전부 넣는다), `compatibility`(필요한 도구·의존성, 선택), 그리고 본문.

사용자의 전문 용어 수준에 맞춰 말투를 조절하라는 안내도 들어 있다 (예: "JSON", "assertion"은 사용자가 아는 것 같을 때만 설명 없이 쓴다).

## 이 볼트와 이어지는 점

- 이 볼트의 스킬(`/save`, `/scout`, `/inbox-batch` 등)도 같은 SKILL.md 형식이라, 새 스킬을 만들거나 기존 스킬을 평가·개선할 때 이 스킬을 쓸 수 있다.
- 특히 "만들고 → 테스트 프롬프트로 돌려 보고 → 평가해서 고친다"는 순서는, 이 세션에서 `/save`를 쓰며 규칙을 하나씩 고쳐 온 방식과 같다.
- 소개 글은 비전문가용이라 "평가" 부분이 빠져 있다. 스킬이 제때 불리는지(description)와 결과가 맞는지를 확인하는 단계가 실제로는 핵심이다.

## 참고

- skill-creator의 SKILL.md는 앞부분을 읽었다. 평가 도구(`eval-viewer`)와 description 개선 스크립트의 세부는 확인하지 못했다.
