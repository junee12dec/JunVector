# YC QM — 스타트업 전체를 에이전트로 돌리는 멀티 에이전트 하네스

- 공식 사이트: https://qm.ycombinator.com
- GitHub: [yc-software/qm](https://github.com/yc-software/qm)
- 공개 15시간 만에 조회수 100만(1M)
- 라이선스: MIT

> "코딩 에이전트한테 '이 레포를 배포해'라고 시키세요." — 설치 안내 전문

## 배경: Hermes 50대를 돌리다 한계

1. Ruby 루프 에이전트 → 좁음
2. Hermes 에이전트 50대 운용 → 관리 한계
3. 목표 재정의: **"Hermes만큼 유연하되, 처음 시스템만큼 단순하게"** → QM

이름: **Quartermaster** (갑판 아래에서 물자와 질서를 챙기는 직책)

## 설계 원칙

### 조직 단위 설계
- 직원마다 **격리 워크스페이스** 제공
- 사람·방 단위로 메모리·파일·권한·크론·샌드박스 분리
- Slack 채널·프로젝트에 그대로 통합

### YC 실제 운용 영역
- 회계, 법무, 이벤트, 엔지니어링
- QM을 고치는 작업도 QM 안에서 수행

## 아키텍처

```
중앙 코어
  ← 하네스: Pi / OpenCode / Codex / Claude Code (교체 가능)
```

특정 벤더에 묶이지 않는 구조. 하네스를 언제든 갈아 끼울 수 있음.

## 보안 모드 3단계

| 모드 | 설명 |
|------|------|
| **Strict** | 툴 호출 대부분 사람 승인 필요 |
| **Auto** (기본) | 분류기가 외부 데이터·툴 결과를 먼저 거른 뒤 모델에 전달 |
| **Dangerous** | 검사·정지 없음 (단, 재귀 삭제·파괴적 SQL은 어느 모드든 정책으로 차단) |

## 설치 방식 (에이전트가 설치)

```bash
qm init  # 배포용 스킬 생성
# → 에이전트가 인프라 설정·로그인·커넥터 연결·배포·검증 진행
```

레포 내 `.claude/skills` · `.codex/skills` 폴더 기본 내장.  
**이 소프트웨어의 첫 독자는 사람이 아니라 에이전트.**

## 핵심 인사이트

> "우리는 말도 안 되게 작은 팀으로 남아 있는데, 아웃풋은 군대처럼 나온다."

에이전트에게 시키는 단위가 **개인 → 조직**으로 이동 중.  
다음 소프트웨어는 여러분이 설치하지 않는다. 여러분의 에이전트가 설치한다.
