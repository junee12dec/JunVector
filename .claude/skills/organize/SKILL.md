# /organize 스킬

`01-inbox/`의 노트를 읽고 PARA 폴더로 이동한 뒤, 해당 폴더의 MOC를 업데이트한다.

---

## 실행 절차

### 1단계 — 대상 노트 확인

- 특정 노트가 지정된 경우: 해당 노트만 처리한다.
- 노트가 지정되지 않은 경우: `01-inbox/`의 전체 노트 목록을 보여주고 선택을 요청한다.

```
01-inbox에 노트가 N개 있어:

1. [[파일명]] — description 한 줄
2. [[파일명]] — description 한 줄
...

어떤 노트를 정리할까? (번호 / "전체" / 파일명)
```

### 2단계 — PARA 분류 판단

노트의 frontmatter(`title`, `tags`, `description`)와 본문을 읽고 아래 기준으로 분류한다.

| 폴더 | 판단 기준 |
|------|-----------|
| `03-projects/` | 완료 기한이 있는 작업. "~를 만든다", "~를 완성한다"처럼 끝이 명확한 것 |
| `04-areas/` | 지속적으로 유지·관리하는 책임 영역. 건강, 재무, 학습, 커리어 등 끝이 없는 것 |
| `05-resources/` | 특정 프로젝트에 속하지 않는 참고 자료, 관심사, 레퍼런스 |
| `06-archives/` | 이미 완료되었거나 더 이상 활성화하지 않는 것 |

판단 결과를 이동 전에 사용자에게 보여주고 확인받는다:

```
분류 결과:

[[파일명]] → 05-resources/
이유: 특정 프로젝트에 속하지 않는 AI 도구 참고 자료

이동할까? (Y / 다른 폴더 지정)
```

- 판단이 애매한 경우: 이유와 함께 두 가지 후보를 제시하고 선택을 요청한다.
- 여러 노트를 한 번에 처리할 때는 전체 분류 결과를 먼저 보여준 뒤 한 번에 확인받는다.

### 3단계 — 노트 이동

사용자 확인 후 노트를 대상 폴더로 이동한다.

- 이동 경로: `01-inbox/<파일명>.md` → `<대상폴더>/<파일명>.md`
- 파일명은 변경하지 않는다.
- `01-inbox/MOC.md`의 해당 노트 링크를 제거한다.

### 4단계 — 대상 폴더 MOC 업데이트

이동한 폴더의 `MOC.md` "노트 목록" 섹션에 링크를 추가한다.

```markdown
- [[파일명|노트 제목]] — 날짜
```

MOC에 적절한 소제목(예: `### 주제별`)이 있으면 그 아래에 추가하고, 없으면 목록 끝에 추가한다.

### 5단계 — 완료 보고

```
완료:

[[파일명]] → 04-areas/
MOC 업데이트: [[04-areas/MOC]]

다음으로 무엇을 할까?
A. 딥다이브 — 이 노트 주제를 더 깊이 탐구 (/deep-dive)
B. 계속 정리 — inbox의 다른 노트 정리
C. 종료
```

---

## 전체 흐름 요약

```
대상 노트 확인
  → 노트 내용 읽기
  → PARA 분류 판단 & 이유 제시
  → 사용자 확인
  → 노트 이동 (inbox MOC에서 링크 제거)
  → 대상 폴더 MOC에 링크 추가
  → 완료 보고 & 다음 행동 제안
```

---

## 주의사항

- 이동 전에 반드시 사용자 확인을 받는다. 확인 없이 파일을 이동하지 않는다.
- 판단 근거를 항상 한 줄로 함께 제시한다.
- 여러 노트를 처리할 때는 파일을 하나씩 이동하되, 확인은 전체를 한 번에 받아도 된다.
- `02-daily-notes/`와 `99-meta/`로는 이동하지 않는다. 이 폴더는 organize 대상이 아니다.
