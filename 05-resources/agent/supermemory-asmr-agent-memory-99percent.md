# Supermemory ASMR — 벡터 DB 없이 에이전트 메모리 98.6% 달성

Supermemory가 LongMemEval 벤치마크에서 98.6%를 기록했다. 벡터 DB를 쓰지 않고. 이전 자체 기록 85%에서 몇 달 만에 13포인트를 올렸다.

기법 이름은 **ASMR — Agentic Search and Memory Retrieval**.

---

## LongMemEval이란

AI 메모리 벤치마크 중 가장 까다로운 테스트.

- 11만 5천 토큰 이상의 대화 기록
- 50개 세션에 걸쳐 흩어진 정보
- 서로 모순되는 팩트
- 시간 순서를 추론해야 하는 질문

500개 질문을 6개 카테고리로 테스트한다:
1. 단일 세션 정보 추출
2. 다중 세션 추론
3. 시간 추론
4. 지식 업데이트
5. 기권 (모르면 모른다고 답하기)

대부분의 메모리 시스템이 무너지는 구간은 **"시간 추론"**과 **"지식 업데이트"**다.

> "서울에 산다"고 했다가 나중에 "샌프란시스코로 이사했다"고 하면, 최신 정보가 뭔지 구별해야 한다. 벡터 유사도 검색으로는 이게 안 된다.

---

## 왜 벡터 검색이 한계인가

기존 RAG 방식의 문제:

- 텍스트를 임베딩으로 변환하고, 질문이 들어오면 가장 비슷한 벡터를 찾아 넘긴다
- "의미적 유사도"에 의존한다
- "서울에 산다"와 "샌프란시스코로 이사했다"는 둘 다 "사는 곳" 관련 문장 → 벡터 검색은 둘 다 가져오고, 어느 게 최신인지 모른다

Supermemory의 선택: **벡터 검색을 아예 버렸다.**

---

## ASMR 아키텍처

### 1단계 — 병렬 읽기 (Observer Agents)

3개의 읽기 에이전트를 병렬로 띄운다 (Gemini 2.0 Flash 기반).

| 에이전트 | 역할 |
|----------|------|
| Observer 1: Fact Hunter | NER, 명시적 진술 추출, 관계 매핑 |
| Observer 2: Context Weaver | 패턴 인식, 세션 간 상관, 의미 클러스터링 |
| Observer 3: Timeline Tracker | 시간 순서 추출, 이벤트 연대기, 지식 업데이트 감지 |

- Round-robin 방식으로 세션 분배 (1,4,7... / 2,5,8... / 3,6,9...)
- 6가지 축으로 정보 추출: 개인 정보, 선호도, 이벤트, 시간 데이터, 업데이트, 어시스턴트 정보
- 구조화된 결과를 원본 세션에 매핑해 저장 — **임베딩 없이**

### 2단계 — 에이전트 검색 (Search Agents)

질문이 들어오면 벡터 DB 쿼리 대신 3개의 검색 에이전트를 병렬로 띄운다:

| 에이전트 | 역할 |
|----------|------|
| Search Agent 1: Direct Seeker | 직접적 사실, 명시적 진술, 최신 우선 검색 |
| Search Agent 2: Inference Engine | 관련 맥락, 사회적 단서, 함축 분석 |
| Search Agent 3: Temporal Reasoner | 시간 타임라인 재구성, 상태 변화 추적 |

오케스트레이터가 세 에이전트의 결과를 종합하고 원본 세션에서 해당 부분을 직접 뽑아 검증한다. **수학적 유사도가 아닌 인지적 이해 기반 검색.**

### 3단계 — 앙상블 답변

두 가지 실험:

**8-Variant 앙상블 (98.60%)**
- 8개의 전문화된 프롬프트 변형을 병렬 실행
- 정밀 카운터, 시간 전문가, 맥락 심층 분석 등
- 8개 중 하나라도 정답에 도달하면 성공

**12-Variant 의사결정 포레스트 (97.20%)**
- 12개의 전문 에이전트가 독립적으로 답변 (GPT-4o-mini 기반)
- 집계 LLM이 다수결 투표 + 도메인 신뢰도 + 충돌 해결로 최종 답 도출

## LongMemEval 경쟁 현황

| 시스템 | 정확도 | 특이사항 |
|--------|--------|----------|
| **Supermemory ASMR** | **98.60%** | 벡터 DB 없음, 실험적 |
| Supermemory 12-Variant | 97.20% | 단일 합의 답변 |
| OMEGA | 95.4% | MCP 서버, 25개 도구 |
| Mastra | 94.87% | gpt-5-mini 기반, 오픈소스 |
| Ensue | 93.2% | gpt-5-mini 기반 |
| Hindsight | 91.4% | 그래프+시간 인식 검색 |
| Supermemory (이전) | ~85% | 프로덕션 엔진 |
| Zep | 71.2% | 시간 지식 그래프 |

1위와 2위 사이 갭이 3포인트. 메모리 전쟁이 매우 치열하다.

## 솔직하게 짚을 것

Supermemory 팀 스스로 인정한 한계:

- 이건 **프로덕션 엔진이 아니다**. 절대 한계를 탐색하려고 만든 실험적 에이전트 플로우
- 프로덕션 제약(레이턴시, 비용)을 무시한 수치
- 8개 변형 병렬 실행 + 하나라도 맞으면 성공 → 실전에서 토큰 비용이 너무 많이 든다

**핵심 인사이트는 유효하다**: "벡터 검색 대신 에이전트가 직접 읽고 추론하면, 시간/업데이트 문제를 근본적으로 해결할 수 있다." — Mastra, Ensue, Hindsight 등 다른 팀들도 이 방향으로 수렴 중.

---

## 왜 중요한가

에이전트 메모리는 편의 기능이 아니다. 에이전트가 장시간 자율적으로 일하려면 지난 대화를 정확하게 기억하는 게 전제 조건이다.

- Anthropic 에이전트 하네스 논문의 35분 성능 저하 문제
- 컨텍스트가 커지면 에이전트가 방향을 잃는 현상
- 근본 해결책: **필요한 기억만 정확하게 꺼내오는 시스템**

임베딩 파이프라인 없이 인메모리에서 동작 → 임베디드 환경(로봇 등)에도 적용 가능.
