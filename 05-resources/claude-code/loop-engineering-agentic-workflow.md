# 루프 엔지니어링 — 프롬프트 대신 자동화 루프 설계하기

## 핵심 인사이트

> "나는 이제 Claude에게 프롬프트를 쓰지 않는다. 내 일은 루프를 작성하는 것이다."
> — Boris Cherny, Claude Code 개발자

AI 엔지니어링의 4단계 진화:

| 시대 | 연도 | 패러다임 |
|------|------|---------|
| **프롬프트** | 2022 | 메시지 하나 → 답변 하나 |
| **컨텍스트** | 2024 | 문서·윈도우로 모델에게 맥락 제공 |
| **하네스** | 2026 | 도구와 체크로 모델을 구조화 |
| **루프** | 현재 | 목표 → 스스로 실행하는 시스템 |

---

## 6단계 에이전트 루프

### 1. 표준 정의 (Standards)
`/init` → `CLAUDE.md`

- `/init`를 실행하면 Claude가 CLAUDE.md 파일을 생성
- 목소리, 규칙, 금지 단어를 한 번만 작성하면 매 작업마다 자동 로드
- "두 번 다시 브리핑하지 않아도 되는 브리프"

```
/init CLAUDE.md에 내 목소리를 저장: 영국식 영어, em 대시 금지, 내 훅 스타일.
```

**왜**: 매번 새로 설명할 필요 없이 표준이 모든 작업에 상속된다.

---

### 2. 목표와 마감선 (Goal)
마감선 = 루프의 종료 조건

- 원하는 결과와 채점 기준(rubric)을 함께 명시
- "95점이 될 때까지 멈추지 마라" → 점수가 루프의 off-switch

```
/goal 내 루브릭으로 채점하고, 95/100이 될 때까지 멈추지 마.
```

**왜**: 마감선이 없으면 루프가 없다.

---

### 3. 팀 구성 (Team)
서브에이전트 분업

- 전략가(Strategist): 방향 선택
- 작가(Writer): 초안 작성
- 디자이너(Designer): 레이아웃

```
/agents 팀 구성: 전략가, 작가, 디자이너. 각각 하나의 명확한 역할.
```

**왜**: 한 명의 제너럴리스트보다 전문화된 스페셜리스트 팀이 낫다.

---

### 4. 검사기 추가 (Eval)
LLM-as-Judge 패턴

- 별도 에이전트가 매 초안을 루브릭으로 채점
- 95점 미만이면 한 가지를 수정하고 재실행
- 자기 숙제를 스스로 채점하지 않는다

```
/agents QA 에이전트 추가: 초안을 100점 만점으로 채점하고 95 미만은 반려.
```

**왜**: 이것이 LLM-as-Judge라는 명명된 패턴이다.

---

### 5. 기억 저장 (Memory)
`MEMORY.md`

- 모든 수정사항이 규칙으로 저장
- 매 실행 시작 때 리로드
- 시간이 갈수록 점점 더 나를 닮아간다

```
/memory 모든 수정을 규칙으로 저장하고, 매 실행 때 리로드.
```

**왜**: 실수는 한 번만. 두 번은 없다.

---

### 6. 스케줄 등록 (Schedule)
클라우드 루틴

- 루프 전체를 Routine으로 감싸기
- 노트북을 닫은 채로 Anthropic 클라우드에서 실행
- 아침에 일어나면 완성된 초안이 대기 중

```
/schedule 평일 오전 7시에 내 콘텐츠 루프 실행. 초안은 검토 대기.
```

**왜**: 한 번 설정하면 자는 동안 알아서 돌아간다.

---

## 루프의 구조

```
컨텍스트 수집 → 행동 → 검증 → 반복
```

목표에 도달할 때까지 스스로 순환하는 시스템.
