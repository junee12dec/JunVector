# Obsidian 그래프뷰 5종 비교

> "멋진 그래프가 아니라 다시 찾을 수 있는 구조가 진짜 중요하다."

---

## 노드 수에 따른 그래프의 현실

| 노드 수 | 상태 |
|---------|------|
| ~50개 | 감성 |
| ~200개 | 혼돈 시작 |
| 1,000개+ | 별자리 감상 (지식 탐색 X) |

---

## 5종 비교

### 기본 Graph View
- 가장 안정적
- 전체 구조 확인용
- 대형 Vault에 상대적으로 강함
- 단점: 연결의 의미 해석이 어려움

### 3D Graph View
- 비주얼 최강, 디지털 브레인 느낌
- 발표·데모·시연용으로 적합
- 단점: 실사용 탐색에서 피로감

### Juggl
- 프로젝트 단위 사고 정리
- 화이트보드처럼 구조화 가능
- 노드 스타일링·배치 강점
- 단점: 노드 많아지면 성능 저하

### Living Graph
- 움직이는 그래프 — 감성·영상·시연용
- 단점: 노트북 팬이 같이 살아남

### Extended Graph
- 기본 그래프의 현실적 확장판
- 이미지·속성·필터 표현 강화
- 업무용으로 가장 무난

---

## 상황별 선택 기준

| 상황 | 선택 |
|------|------|
| 전체 지식 구조 파악 | 기본 Graph View |
| 업무용 일상 탐색 | Extended Graph |
| 프로젝트 생각 정리 | Juggl |
| 발표·데모 | 3D Graph View |
| 감성 시연·영상 | Living Graph |

---

## 핵심 인사이트

> "디지털 브레인은 좋은데, 너무 커진 브레인은 그냥 예쁜 우주가 됩니다."

그래프가 과시용이나 에이전트용이 아니라 **사람이 실제로 쓰는 구조**가 되려면,
노드 수보다 **재탐색 가능한 구조 설계**가 먼저다.
